## Отклонения

- В режиме одного прохода этапы 1–2 не вливались в `main`. Поэтому требование «сравнить RU с main» трактуется как сравнение с семантическим `main` этапа 3 — checkpoint `40b2a41`, где уже завершены этапы 1–2. Это ближайший буквальный эквивалент описанного в спецификации `main` с влитыми предыдущими этапами.
- Один сериализованный fixture нельзя безопасно использовать сразу для обеих ревизий: `40b2a41` хранит world v3 с готовыми текстами событий и строковыми ошибками, а Stage 3 — world v4 с `params`/`variant` и `EngineError`. Поэтому `check-i18n` независимо строит одинаковые сценарии через `createWorld` / `applyAction` внутри каждой обслуживаемой ревизии и до UI-сравнения проверяет совпадение seed/week/action/events. Так Stage 3 проверяет новый RU formatter, а не legacy-путь миграции v3.
- `npm run sim` печатает фактическое время выполнения в заголовке. Сначала сохраняются полные выводы; для проверки баланса дополнительно сравнивается вывод с нормализованным только этим полем времени. Любое другое отличие считается нарушением баланса.
- `dreamView` до этапа 3 выдавал текстовую причину «Не хватает N монет», тогда как спецификация перечисляет коды `beforeFreedom | done | building`. Недостаток денег хранится отдельно как `missingCash`, чтобы движок не собирал пользовательский текст, а UI показывал прежнюю RU-фразу.
- `/en/` принудительно выбирает EN при первоначальной загрузке/перезагрузке. После загрузки явный переключатель RU разрешён и действует мгновенно; иначе требование переключения языка посреди партии конфликтовало бы с `/en/ → английский всегда`.
