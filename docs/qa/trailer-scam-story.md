# Приёмка: понятная история с аферой в рекламном ролике

Дата: 2026-10-08. Ветка: `chat/trailer-scam`; база: `origin/main` после слияния PR #8 (`f67b4e8`).
Спецификация: [`docs/specs/trailer-scam-story.md`](../specs/trailer-scam-story.md).

## Суть изменения

Игровая карточка «Жемчужная ферма» теперь ведёт к двум последовательным сценам на острове:
`scam-card` (обещание дохода) → `scam-pays` (два начисления) → `scam-collapse` (потеря денег,
исчезновение фермы и прямое объяснение пирамиды). Числа должны считываться из неизменённого
`fixtures.json`/`offerViews`, а не вводиться константами вместо данных игры.

Проверены исходные данные `scamCard.world.offers`: `pearlFarm` стоит **900** монет,
её ожидаемый недельный доход — **213**. Две выплаты в кадре — `+213`, потеря в обвале — `−900`.
Исходный `S=23`; к `heroItemsByWeek[S]` для сцен добавляется экранный объект
`{ uid: 'director-pearl', model: 'pearlFarm', slot: 'sea', slotIndex: 0, level: 1 }`.

### Точечные рендер-проверки

Через `npm run trailer -- --quality draft --format all --lang all --shots scam-collapse --no-build`
проверены **4/4** варианта `scam-collapse` (v30/h45 × RU/EN): сцена, удаление фермы,
видимая без перекрытия отрицательная сумма не менее секунды, две строки подписи,
постоянная высота и контрольные проекции. Результат — **PASS**.
Проверки `scam-card`/`scam-pays` прошли по всем форматам и языкам,
в том числе после окончательной коррекции визуализации и удержания заголовка.

Полный `npm run trailer -- --quality draft` — **PASS**: созданы
`docs/qa/trailer/draft/archipelago-v30-ru.mp4` (**2 299 705 байт**),
`archipelago-h45-ru.mp4` (**3 438 394 байт**), два JPEG-листа
(246 364 и 381 480 байт) и `timeline.md`. Оба видео укладываются в 5 MiB,
оба листа — в 400 KiB; sourceHash `bcc44035f29c00d127174f1e4076b3b29ad3dda422ff6558f2911ab57088265d`.
Все пять вошли в `dcbaf6d` и после исправления границ в `83269bd`, оба коммита отправлены в remote.

При покадровом просмотре выявлена и исправлена особенность виртуального времени: ранее
анимация только что возникшей суммы начиналась с накопленного времени страницы и почти
немедленно становилась прозрачной. Рендер теперь ведёт отдельное время рождения CSS-анимаций
`.isl-float-inner` только в новых сценах. Дополнительно в вертикальном `scam-collapse`
отрицательная сумма смещена ниже подписи; проверка требует **неперекрытых** кадров,
а не одного наличия суммы в DOM.

## Отклонения и запасные варианты

**Окончание `scam-card`.** Бриф одновременно требует сохранить исходную покупку и видеть
заголовок карточки на *каждом* кадре. В исходном UI `buyOffer` немедленно удаляет купленное
предложение и выводит вместо него другую карточку и уведомление; это было обнаружено на
последнем тестовом кадре. Ближайший к цели ролика вариант по таблице
[`launch.md`](../specs/launch.md#режим-одного-прохода): время видимого нажатия
и звук `ui.click` остаются прежними (`длина − 0,75` доли), но исполнение действия
отложено за склейку. Благодаря этому зритель успевает дочитать приманку, затем отдельная
сцена показывает уже приобретённую ферму. Игровая логика и `fixtures.json` не меняются.

**Временная шкала CSS-анимаций.** Виртуальные часы первоначально прикладывали абсолютное
время страницы к новой анимации `isl-rise`, из-за чего выплаты были почти невидимы.
Скрипт рендера теперь учитывает время возникновения анимации только для плавающих сумм
в новых сценах, сохраняя остальные кадры и игру без изменений.

**Остаточные кадры в кэше PNG.** Первое полное кодирование final v30-ru остановилось
по автоматической проверке длительности (`30.067` с вместо 30 с): после изменения
границ shots кэш сохранил PNG сверх нового `frames`, и `ffmpeg -i %05d.png`
захватил часть старых кадров. Исправлено `encodeSegment(..., frames)` с
`-frames:v <точное количество>`; draft повторно кодируется из актуального префикса
PNG, затем финалы повторно запускаются с тем же исправлением. Исходные игровые кадры
не удаляются и `fixtures.json` остаётся неизменным.

**Запас по истинному пику.** Первый полный рендер после устранения проблемы с
длительностью остановился на `h45-ru` с измеренным `−0,9 dBTP`, то есть выше
допустимого `−1 dBTP`. Не меняя музыку, игровые звуки или баланс, мастеринг
`scripts/trailer/audio.mjs` переведён на запас `TP=−2,5` вместо `−1,5` при
неизменной цели `I=−14 LUFS`. Точечный повторный финальный `h45-ru` прошёл
автоматическую проверку; затем запущен общий рендер четырёх версий.

При последующих неоднозначностях действует та же таблица запасных вариантов;
технические невыполненные пункты, если возникнут, будут записаны здесь без остановки этапа.
