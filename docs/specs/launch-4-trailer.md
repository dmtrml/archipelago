# Этап 4. Рекламный ролик

Исполнитель: агент-разработчик (Codex). Проверяющий: Claude. Один PR из ветки `codex/launch-4-trailer`,
от `main` с влитыми этапами 1–3. Общие правила и решения владельца — в [launch.md](launch.md).

Цель: четыре ролика из настоящей игры — `v30` (вертикальный 1080×1920, 30 с) и `h45` (горизонтальный 1920×1080, 45 с),
каждый по-русски и по-английски. Кадры снимает сама игра в специальном режиме съёмки, покадрово и в
виртуальном времени. Монтаж под музыку, звук — звуки самой игры. Всё воспроизводимо одной командой.

Ни исполнитель, ни проверяющий не видят видео в движении и не слышат звук. Поэтому работа идёт в два круга:
**черновик → правки владельца с таймкодами → финал** (раздел «Порядок работы»).

## Как это устроено

```
scripts/trailer/fixtures.ts   движок → apps/web/src/director/fixtures.json (миры для игровых кадров, рост острова)
apps/web/src/director/        режим съёмки ?director: кадры, подписи, камера, финальная карточка
scripts/trailer/render.mjs    Playwright + виртуальное время → PNG-кадры → ffmpeg → MP4
scripts/trailer/audio.mjs     журнал звуков кадров → офлайн-рендер звуков игры → сведение с музыкой
scripts/trailer/beats.mjs     проверка темпа музыки (99 BPM)
```

Кадры двух типов:

- **сцена** — только 3D-остров без интерфейса, как в песочнице: режиссёр сам задаёт объекты, всплывающие суммы,
  погоду, мечту и камеру;
- **игра** — настоящий интерфейс с настоящим миром из `fixtures.json`; режиссёр нажимает за игрока
  через стор (`useGame.getState().act / endWeek / setTab …`), а игра сама показывает окна, суммы и конфетти.

## Что уже проверено (черновая проверка Claude, 2026-10-05)

- **Виртуальное время работает.** Init-скрипт подменяет `performance.now`, `Date.now`, `setTimeout`/`setInterval`,
  `requestAnimationFrame` и `Math.random` (с seed). Каждый шаг двигает время на 1/fps, вызывает таймеры и кадр
  R3F и выставляет `currentTime` всем CSS-анимациям через `document.getAnimations()`. Сцена 360×640 при dpr 3
  снималась примерно за **0,67 с на кадр** в программном рендере (SwiftShader, 4 ядра; dpr сцены тогда был
  ограничен 2). Два прогона дали одинаковые кадры: совпадение или PSNR ≈ 59 дБ. Пружинка появления лодки,
  круг на воде, всплывающая сумма и тост снимаются плавно.
- **Подводные камни:**
  1. Пока страница грузится, время надо «прокачивать» (`step(16)` + 20 мс реального ожидания): React и Vite ждут
     таймеров, без этого ничего не отрисуется.
  2. Не нажимать элементы через Playwright `click()` — проверка готовности элемента может зависнуть при
     замороженном rAF. Режиссёр действует через стор; если нужен DOM-клик — `element.click()` в `page.evaluate`.
  3. Шрифты должны быть локальными (сделано в этапе 1). Иначе в кадрах окажется запасной системный шрифт.
- **Музыка:** Happy Ukelele Island Surfing Theme (`apps/web/public/audio/music/island-ukulele.mp3`, CC0) — ровно
  **99,00 BPM**, первая доля на **0,023 с** (поиск по гребёнке энергетического потока, шаг 0,05 BPM).
  Доля `B = 60/99 с ≈ 0,60606 с`. 30 с = ровно 49,5 доли, 45 с = ровно 74,25 доли.
- **Игровые кадры находятся.** Критерии из раздела «Миры для игровых кадров» в черновой проверке выполнил
  уже seed 2: свобода на 30-й неделе, ферма на 23-й, обвал на 27-й, соседи — 8-я неделя.

## Разрешённые изменения вне новых файлов — полный список

1. `apps/web/src/main.tsx` — ленивый маршрут `?director` (как `?sound` и `?sandbox`).
2. `apps/web/src/store.ts` — одна строка: `SAVE_KEY = 'archipelago.director.save'`, если в адресе есть `director`.
   Так открытый у владельца `?director` не затрёт его настоящее сохранение.
3. `apps/web/src/scene/contract.ts`, `IslandScene.tsx` и новый `scene/DirectorCamera.tsx` — необязательные пропсы
   `cameraPose?: () => CameraPose` и `dpr?: number`, где `CameraPose = { target: [x, y, z]; az; el; d }` в мировых единицах,
   уже с поправкой на формат (см. «Кадры»). С `cameraPose` вместо `CameraRig` работает `DirectorCamera`:
   каждый кадр вызывает функцию, ставит камеру по позе и смотрит на `target`, `zoom = 1`, без `viewOffset`.
   Без этих пропсов сцена работает ровно как раньше.
4. `apps/web/src/audio/synth.ts` — только тип: `synthesize(context: BaseAudioContext, …)` (для `OfflineAudioContext`).
5. `packages/engine/scripts/policies.ts` — политики человека и второго акта переносятся из `scripts/simulate.ts`
   **дословно**. `simulate.ts` их импортирует. У `makeSensible` две новые опции: `study` (по умолчанию `true`;
   `false` — ветка учёбы пропускается) и `avoidScams` (по умолчанию `false`; `true` — из кандидатов на покупку
   исключаются `def.kind === 'scam'`). Вывод `npm run sim` до и после — побайтно одинаковый.
6. Корневой `package.json` — скрипты `trailer` (`node scripts/trailer/render.mjs`) и `trailer:fixtures`
   (`tsx scripts/trailer/fixtures.ts`); dev-зависимости `ffmpeg-static` и `ffprobe-static`
   (переменные `FFMPEG_PATH` / `FFPROBE_PATH` их переопределяют).
7. `.gitignore` — `.trailer/`.

Больше ничего в игре не меняется. Маршрут `?director` уже исключён из аналитики (этап 2).

## Кадры

Поза камеры: `target` (x, y, z), азимут `az` и высота `el` в градусах, расстояние `d`. Положение камеры:
`target + d · (cos el · sin az, sin el, cos el · cos az)`. Азимут — как в `CameraRig` (`atan2(x, z)` от цели);
вид по умолчанию в игре — `az 45°`, `el 23,67°`, `d 68`. Значения `d` даны для 16:9. Для 9:16 они умножаются на
`idealDistance(9/16) / 68 ≈ 1,511` — тем же правилом игра отодвигает камеру на узком экране. Камера едет
от позы «от» к позе «до» **линейно** за весь кадр.

Позы ниже — стартовые значения. Их нужно **откалибровать** по правилам композиции (раздел «Подписи»)
на листах-раскадровках черновика. Итоговые значения записать в `shots.ts` и в документ приёмки.

Ключевые точки (из `scene/slots.ts`): пирс, место 0 — (9,85; 0; 18,94); площадь, место 0 — (0,87; 1,54; 1,72);
бухта, место 0 — (18,72; 0; 8,36); стапель — около (16,0; −6,0), шхуна на воде — около (20,8; −4,4).

Остров для кадров-сцен берётся из «героической» партии (`heroItemsByWeek` в `fixtures.json`, см. ниже):
«неделя w» — `heroItemsByWeek[w]`. Суммы над объектами — те же строки словаря, что показывает игра
(покупка — «+20 в неделю», неделя — «+20»), и тот же тон `pos`/`neg`. Звуки — через `audio.play` с теми же
задержками, что в `gameSounds.ts` (`coins.pay` → `build.pop` через 70 мс → `status.joy` через 160 мс;
`coins.pay` → `upgrade` через 200 мс).

### `hook` — остров растёт на глазах (сцена)
- Объекты: от недели 0 (пустой остров) до недели 100. Все изменения — появления, повышения уровня, исчезновения —
  по порядку недель (внутри недели — по порядку в данных) равномерно распределены на отрезке долей
  [0,5; длина − 0,5]. Каждое изменение — обновление `items`; анимации делает сама сцена.
- Звуки: не больше одного на каждую половину доли — `build.pop` на первое изменение в этой половине,
  `pitchStep` = номер половины от 0, не больше 7.
- Камера: цель (0; −1,2; 0); `az` 30 → 60, `el` 24, `d` 68 → 64.
- Подпись 0,25 → длина − 0,25: «600 монет и маленький остров» / «600 coins and a tiny island».

### `asset` — первый актив (сцена)
- Объекты: неделя 0 (пустой остров). 0,5 — лодка, уровень 1, пирс, место 0 (`coins.pay`, `build.pop`). 1,25 — сумма
  «+20 в неделю» над лодкой. 3,0 — `week.next`. 3,5 — сумма «+20» над лодкой и `coin.tick` (`pitchStep` 0).
- Камера: цель (9,85; 0,6; 18,94); `az` 35 → 50, `el` 26, `d` 30 → 26.
- Подпись 0,5 → длина − 0,25: «**Активы** приносят деньги каждую неделю» / «**Assets** pay you every week».

### `upgrade` — улучшение (сцена, только `h45`)
- Объекты: неделя 0 + лодка уровня 1 на пирсе, место 0 (стоит с начала, без анимации).
  1,0 — уровень 2 (`coins.pay`, `upgrade`), 1,8 — сумма «+12 в неделю». 3,5 — уровень 3, те же звуки;
  4,3 — сумма «+8 в неделю» (разница доходов ступеней из `ASSET_DEFS.boat.upgrades`).
- Камера: цель как у `asset`; `az` 50 → 62, `el` 24, `d` 24 → 22.
- Подпись 0,25 → длина − 0,25: «Улучшайте то, что уже есть» / «Upgrade what you already own».

### `liability` — пассивы (сцена)

### `scam-card` — «Жемчужная ферма» (игра, мир `scamCard`)
- Телефон: `setTab('deals')` (шторка открыта), список `.tab-scroll` прокручен так, что карточка

  «Сделки» правой колонки.

  x 10–90%, y 12–76%. Высота камеры не ниже 15°, расстояние не меньше 18, линия горизонта не режет главный предмет.

## Миры для игровых кадров — `scripts/trailer/fixtures.ts`

Героическая партия. `createWorld({ seed, playerName: 'Вы', islandName: 'Лагуна' })`; человек играет политикой
`makeSensible({ study: false, avoidScams: true })`. Без учёбы знание остаётся 0, и на карточке аферы нет
предупреждения. Короткое название острова — потому что «Тихая Гавань» обрезается в шапке телефона на 360px.
Режиссёр подменяет имена по языку: «Вы» / «Лагуна» и «You» / «Lagoon».

Каждая неделя `w = 1…100`: `runBotTurn(world, 'p1', hero)` → сохранить мир как `beforeEnd[w]` → `applyAction(world, { type: 'endWeek' })`.
Объекты острова — владения игрока без слота `finance`.

Перебирать `seed = 1, 2, 3…` до первого, где выполнено всё ниже. Если до 50 000 такого нет — остановиться и написать вопрос.

- **A. Свобода:** достигнута на неделе `F` ∈ [18; 40]; в отчёте этой недели нет общих событий, а у игрока все события —
  `freedom`; доля свободы `beforeEnd[F]` ≥ 0,85.
- **B. Остров к свободе:** в `beforeEnd[F]` не меньше 6 объектов, не меньше 4 разных сделок, есть лодка.
- **C. Афера:** самая ранняя неделя `S` ∈ [5; F − 3], где в `offerViews(beforeEnd[S])` есть `pearlFarm`, на острове ≥ 3 объектов,
  знание 0. Если наличных меньше цены — кредит на `ceil((цена − наличные) / 100) × 100`, если это не больше `loanLimit`,
  иначе неделя не подходит. Мир после кредита — `scamCard`. Дальше покупка фермы, затем до 8 раз `endWeek` без действий
  человека, пока в отчёте не появится `scamCollapse`. Подходит, только если в отчёте с обвалом нет общих событий,
  а у игрока только `scamCollapse`. Мир перед этим `endWeek` — `scamCollapse`.
- **D. Соседи:** самая ранняя неделя `N` ∈ [8; F − 2], где разброс долей свободы четырёх игроков в `beforeEnd[N]` ≥ 0,25,
  а `endWeek` этой недели даёт ноль общих событий, ноль событий игрока и хотя бы одну новость от соседа.
  `beforeEnd[N]` — мир `neighbors`.
- Мир `freedom` — `beforeEnd[F]`.

Каждый мир сохраняется в формате сохранения стора `{ world, news, history }`. `news` и `history` накапливаются
так же, как в `store.ts` (`endWeek` и `recordHistory`): логику повторить в скрипте, `store.ts` не импортировать.
Плюс `heroItemsByWeek` — объекты острова в формате `PlacedItem`: `[0]` — пустой остров до первого хода, `[w]` — объекты в `beforeEnd[w]` для `w = 1…100`. Плюс `seed`, `F`, `S`, `N`.
Файл детерминирован. Два запуска дают побайтно одинаковый `fixtures.json`. Размер — до 400 КБ.

## Режим съёмки — `apps/web/src/director/`

- Адрес: `?director&shot=<id>&format=<v|h>&lang=<ru|en>`; `?director&edit` — отдаёт монтаж;
  `?director&audio` — страница офлайн-рендера звуков.
- `shots.ts` — **единственный источник** кадров и монтажей (таблицы и описания выше в виде данных).
  `render.mjs` читает монтаж из `window.__director.edit` на странице `?director&edit` и сам его не дублирует.
- Кадр-игра: до загрузки `App` режиссёр кладёт мир в `archipelago.director.save`, пишет `archipelago.coach.v1 = "done"`
  и язык; затем рендерит `<div id="director-stage"><App /></div>` и поверх него — слой подписей и индикатора нажатия
  (вне `#director-stage`, чтобы наезд их не масштабировал).
- Кадр-сцена: `<IslandScene items floats weather dream cameraPose dpr={devicePixelRatio} />` и слой подписей.
- Звук в режиме съёмки не играет, `AudioContext` не создаётся. Все публичные методы объекта `audio` из `audio/engine.ts`
  подменяются: `play` пишет в `window.__director.cueLog` запись `{ t, cue, pitchStep?, variant? }`, где `t` — время кадра
  плюс `delayMs`; `setWeather` пишет `{ t, weather }`; остальные ничего не делают. Подмена ловит и звуки, которые игра
  сама играет в кадрах-играх.
- `window.__director = { ready, start(), cueLog, edit, errors }`. `ready` становится `true`, когда загружены мир или сцена,
  выполнено `document.fonts.check('700 20px Unbounded')` и `document.fonts.check('800 16px Manrope')` и сцена отрисовала
  первый кадр. Если шрифтов нет, `errors` не пуст и рендер падает.

## Рендер — `scripts/trailer/render.mjs`

Запуск: `npm run trailer -- [--quality draft|final] [--format v30|h45|all] [--lang ru|en|all] [--shots a,b] [--channel msedge] [--no-build]`.
По умолчанию `draft`, `all` форматов; язык — `ru` для черновика и `all` для финала.

| | `v30` | `h45` |
|---|---|---|
| Вьюпорт (CSS) | 360×640 | 1280×720 |
| dpr: финал / черновик | 3 / 1,5 | 1,5 / 0,75 |
| Кадр: финал / черновик | 1080×1920 / 540×960 | 1920×1080 / 960×540 |
| Частота: финал / черновик | 30 / 15 | 30 / 15 |

1. `npm run build` (если нет `--no-build`), `vite preview` на свободном порту, дождаться ответа 200.
2. Для каждого кадра каждой версии — **новый контекст браузера** с init-скриптом виртуального времени
   (как в «Что уже проверено»: seed `Math.random` — 12345, эпоха `Date` — 2026-10-05T12:00:00Z).
   Открыть адрес кадра; прокачивать время, пока не `ready` (не дольше 600 шагов, иначе ошибка);
   прогрев — 30 шагов по 1/30 с при камере в позе начала; затем `start()`.
3. Кадры: `step(1000 / fps)` → `page.screenshot({ type: 'png' })` → `.trailer/frames/<quality>/<версия>-<язык>/<кадр>/00000.png…`.
   Ошибка или `pageerror` в консоли — рендер падает. Для `en` в начале и в конце кадра в `document.body.innerText`
   нет кириллицы.
4. Кэш кадров. Рядом с кадрами — `done.json` с хешем описания кадра, монтажа, качества, языка и хешем содержимого
   `apps/web/src`. Совпадает — кадр не пересъёмывается. Так правки владельца пересъёмывают только изменённые кадры.
5. Сборка. Каждый кадр — отдельный сегмент `libx264 -preset slow -crf 18 -pix_fmt yuv420p -r 30` (черновик — `-crf 28 -r 15`),
   затем склейка через concat demuxer без перекодирования, звук (ниже) — AAC 192 кбит/с, 48 кГц, стерео,
   `-movflags +faststart`. Профиль H.264 High.
6. Результат в `.trailer/out/<quality>/`: `archipelago-<версия>-<язык>.mp4`; обложка `cover-<версия>-<язык>.jpg`
   (кадр `end` на доле 3,0, JPEG q90); лист-раскадровка `sheet-<версия>-<язык>.jpg` — кадр на каждой доле, ширина 216px (`v30`)
   или 384px (`h45`), по 10 в ряд; `timeline.md` — таблица кадров (доли, секунды, номера кадров, подписи, звуки).

`scripts/trailer/beats.mjs` в начале каждого рендера заново меряет темп и первую долю музыки тем же способом:
ffmpeg → моно 22 050 Гц, окна 512 отсчётов, положительная разность логарифма энергии, перебор 90–110 BPM с шагом 0,05 и фазы.
Ожидается 99,00 ± 0,05 BPM и 0,023 ± 0,02 с. Иначе рендер останавливается с ошибкой.

## Звук — `scripts/trailer/audio.mjs`

- **Журнал звуков версии** — `cueLog` всех кадров со сдвигом на время начала кадра.
- **Каждый звук** рендерится в браузере на странице `?director&audio`: `OfflineAudioContext` (2 канала, 48 кГц).
  Источник — исходный набор владельца `DEFAULT_AUDIO_SOURCES`, а не настройки браузера: синтез — через `synthesize`
  с громкостью `CUES[cue].volume` и высотой `2^(pitchStep/12)`, без случайного сдвига высоты; запись — `decodeAudioData`
  и `playbackRate`. Результат — WAV 32-bit float в `.trailer/audio/cues/`.
- **Природа:** `amb.sea` и `amb.wind` (по набору владельца — синтез) на всю длину. На время кадра `storm` — `amb.rain`
  и `amb.thunder` (записи) с ударами грома раз в 3–6 с (по seed) и ветер ×2,4 (как в игре); на границах кадра — кроссфейды по 0,3 с.
- **Музыка:** `island-ukulele.mp3` с 0,023 с, ровно на длину ролика, затухание на последних 2,5 доли.
  Под каждым `freedom` и `dream.launch` музыка приглушается на 8 дБ на 3 с с плавными спусками по 0,15 с (как в игре).
- **Сведение.** Громкость дорожек мерить через ffmpeg `ebur128`. Музыку довести до −20 LUFS (интегральная), природу — до −32 LUFS,
  эффекты — так, чтобы самое громкое окно 3 с было −14 LUFS. Сложить (`amix`, `normalize=0`), затем двухпроходный
  `loudnorm=I=-14:TP=-1.5:LRA=11` с `linear=true`. Сохранить итог и отдельные дорожки в `.trailer/audio/<версия>-<язык>/`,
  чтобы владелец мог попросить другой баланс.

## Порядок работы

1. **Черновик.** `npm run trailer:fixtures`, затем `npm run trailer -- --quality draft --lang ru`.
   В `docs/qa/trailer/draft/` закоммитить два черновых MP4 (каждый до 5 МБ, иначе `-crf 30`), два листа-раскадровки
   (JPEG до 400 КБ) и `timeline.md`. Открыть PR как черновик: «Ролик: черновик на просмотр».
   В описании — что посмотреть и как писать правки (таймкод + что не так).
2. **Правки владельца** — исполнитель делает **ровно их**, ничего сверх. Новый черновик — если правки крупные
   (перестановка кадров, новые подписи), иначе сразу финал.
3. **Финал.** `npm run trailer -- --quality final` → 4 MP4 и 4 обложки. В git финальные файлы не коммитятся (десятки МБ).
   Если у исполнителя есть права — выложить их ассетами пре-релиза GitHub `trailer-v1`. Если нет — оставить в
   `.trailer/out/final/` и написать в PR, что финал воспроизводится командой `npm ci && npm run trailer -- --quality final`
   (это может сделать владелец или Claude).

## Что не входит

Голос за кадром; другие музыкальные треки и смена трека внутри ролика; тексты постов для соцсетей; новые 3D-модели;
изменения в самой игре сверх «Разрешённых изменений».
