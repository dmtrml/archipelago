# Спецификация: соседи — в верхнюю строку

Исполнитель: агент-разработчик (Codex). Проверяющий: Claude. Объём — небольшой, один PR.

## Контекст

«Архипелаг» — браузерная экономическая игра (React + React Three Fiber, `apps/web`). Соседи-боты показаны
полоской «Гонка к свободе» (`NeighborsBar` в `apps/web/src/ui/Neighbors.tsx`, появилась в PR #2
«Соседи на экране и улучшения активов»). **Начинать от `main`, в который уже влит PR #2.**

Сейчас на компьютере (`.hud.desktop`, ширина ≥ 1024 px):

- верхняя строка (`header.top` в `ui/TopBar.tsx`): слева плашка острова (`.badge`), справа четыре показателя
  (`.stats`), между ними пусто — около 390 px при ширине окна 1400;
- полоска соседей стоит **во второй строке**, в средней колонке (`.col-top` в `ui/Panels.tsx`, стили
  `.col-top`, `.neighbors`, `.nb-*` в `styles.css`), под ней — лента новостей `NewsTicker` и выпадающая
  карточка соседа `NeighborCard`.

На телефоне (`.hud.mobile`) аватары соседей уже стоят в плашке острова (`<NeighborsBar compact />`
в `TopBar`), карточка открывается окном (`NeighborModal`). **Телефон не трогаем.**

Владелец игры хочет, чтобы соседи были **на самом верху — в одной строке с верхним меню**, а не под ним.

## Что сделать

1. **Перенести полоску в верхнюю строку** на компьютере: между плашкой острова и показателями, по центру
   свободного места между ними. Вторая строка (`.col-top`) больше не используется — убрать её разметку и стили.
2. **Три размера полоски по доступной ширине** (не по ширине окна: плашка острова длиннее при длинном
   названии). Удобно через CSS container queries (`container-type: inline-size` на обёртке полоски)
   или `ResizeObserver`:
   - **полный** — как сейчас: подпись «Гонка к свободе», аватар с кольцом прогресса, имя, «N% · M-е»;
   - **средний** — без подписи; аватар, имя и «N%» в две строки, плотнее;
   - **компактный** — только аватары с кольцом прогресса (как на телефоне); имя и процент — в `title`
     (подсказка при наведении) и `aria-label`.
   Пороги подобрать так, чтобы ни на одной ширине из списка проверки полоска не переносилась на вторую
   строку, не наезжала на плашку и показатели и не обрезалась.
3. **Запасной вариант для узких компьютеров** (1024–1200 px): если места не хватает даже на компактный
   размер, полоска не показывается в строке, а аватары встают в плашку острова — так, как это уже сделано
   на телефоне (`NeighborsBar compact` внутри `.badge`; сейчас на компьютере он скрыт правилом
   `.hud.desktop .nb-mini { display: none; }`).
4. **Лента новостей и карточка соседа** выпадают вниз от полоски **поверх острова** (абсолютное
   позиционирование), не меняя высоту верхней строки. Карточка не должна уезжать за край экрана
   и залезать под левую или правую колонку; при узком экране — выравнивание по правому краю полоски.
   Закрытие карточки — как сейчас (крестик, повторный клик по соседу); добавить закрытие по `Escape`.
5. **Поведение не меняется:** клик по соседу открывает/закрывает его карточку, клик по себе ничего не делает,
   кольца прогресса и места считаются как сейчас (`leaderboard()`).

## Чего не делать

- Не трогать движок (`packages/engine`), 3D-сцену (`apps/web/src/scene`) и мобильную раскладку.
- Не менять внешний вид чипов сверх нужного для трёх размеров. Стиль — `docs/ART_DIRECTION.md`
  (матовое стекло, Unbounded для чисел, Manrope для текста, цвета — только токены из `:root`).
- Измерение боковых колонок для 3D-камеры (`useSideInsets` в `App.tsx`) должно продолжать работать:
  оно меряет `.col-left` и `.col-right`, их не переименовывать.

## Как работать в репозитории

```
npm install
npm run dev          # http://localhost:5173
npm run typecheck    # движок + веб
npm test             # тесты движка
npm run build
```

Готовые сохранения для проверки можно сделать через `createWorld` / `applyAction` из `@arch/engine`
и положить в `localStorage` под ключом `archipelago.save.v1` в виде `{ world, news: [] }`.

## Критерии приёмки (по ним проверяет Claude)

1. `npm run typecheck`, `npm test`, `npm run build` проходят; в консоли браузера нет ошибок
   (ошибку сертификата Google Fonts в закрытых сетях можно игнорировать).
2. Скриншоты одной и той же партии (неделя 30+, у соседей разный прогресс, один уже свободен) при размерах
   **1024×768, 1280×720, 1366×768, 1440×900, 1920×1080** и **390×844**:
   - на компьютере соседи в верхней строке, вторая строка над островом свободна;
   - размер полоски соответствует месту, ничего не перекрывается и не обрезается;
   - при длинном названии острова (24 символа) раскладка не ломается;
   - на 390×844 всё как до изменений.
3. Скриншоты открытой карточки соседа на 1366×768 и 1920×1080: карточка поверх острова, целиком на экране,
   не под колонками; закрывается крестиком, повторным кликом и `Escape`.
4. Лента новостей после «Следующей недели» видна под полоской и не сдвигает верхнюю строку.
5. В PR — список изменённых файлов и скриншоты из пунктов 2–3.
